# Walk Moscow

Walk Moscow помогает быстро собрать сценарий пешей прогулки по Москве: пользователь выбирает старт, доступное время, настроение и необязательные места, а сайт предлагает маршрут и открывает его в привычном навигаторе. Регистрация и ключи API не нужны.

## Как устроен проект

- `index.html`, `styles.css`, `app.js` — планировщик прогулки, интерфейс и алгоритм выбора точек;
- `articles.html`, `articles.js` — редакционный гид по местам;
- `sw.js`, `manifest.webmanifest` — устанавливаемая PWA-оболочка;
- `robots.txt`, `sitemap.xml` — базовая SEO-структура.

Маршрут собирается только после нажатия кнопки: изменение полей не создаёт запросы. Координаты используются только после явного запроса геолокации и только в памяти вкладки.

### Внешние сервисы и ограничения

- Leaflet и тайлы OpenStreetMap отвечают за карту;
- публичный OSRM строит пешеходную линию; он может быть временно недоступен или ограничивать нагрузку;
- Nominatim используется только для введённого пользователем поиска и также имеет ограничения публичного сервиса.

PWA сохраняет оболочку сайта и уже просмотренные данные. Это не обещание полноценных офлайн-карт: новые тайлы и построение маршрута требуют сети. Для стабильного роста проекта нужен собственный или коммерческий API маршрутизации.

События продукта вызываются через безопасный `analytics.track(name, payload)` без подключённого счётчика. Чтобы добавить Метрику или другой сервис, нужно предоставить реализацию `window.analytics.track`, не добавляя вымышленные идентификаторы в код.

На GitHub Pages нельзя надёжно задать HTTP-заголовки CSP и Permissions-Policy. Доступны метатеги и осторожный список внешних ресурсов; при переезде на Cloudflare Pages, Netlify или другой хостинг стоит настроить эти заголовки на сервере.

Полный список продуктовых принципов и план развития: [docs/product-principles.md](docs/product-principles.md) и [docs/roadmap.md](docs/roadmap.md).

Веб-приложение с умными пешими маршрутами и гидом по Москве.

Открыть сайт: **[znoynext.github.io/moscow-walks](https://znoynext.github.io/moscow-walks/)**

Основные страницы:

- генератор маршрутов на `index.html`;
- гид по достопримечательностям на `articles.html`.

В гиде собрано 24 места: исторический центр, парки, набережные, музеи, усадьбы и современные районы. Новые карточки добавляются в единый каталог `articles.js` и автоматически появляются на сайте с описанием, фотографией, картой и ссылкой на построение маршрута.

Интерфейс рассчитан на обычных пользователей: техническая выгрузка маршрута убрана.

## Запуск

```powershell
cd "C:\Users\user\Desktop\Вайбкодинг прогулка"
python -m http.server 8013 --bind localhost
```

Открыть:

```text
http://localhost:8013
```

Приложение работает без сборки, npm и API-ключей.

## Бесплатный стек

- Карта: OpenStreetMap через Leaflet.
- Пеший роутинг: публичный OSRM-сервер OpenStreetMap с профилем `foot`.
- Поиск адресов: OpenStreetMap Nominatim.
- Если пешеходный роутер временно недоступен, приложение не рисует ложную прямую через препятствия: показываются точки и понятное сообщение.
- Офлайн-режим: service worker кэширует приложение, Leaflet и уже просмотренные тайлы OpenStreetMap.

Для MVP это полностью бесплатный вариант. Для большого production-проекта лучше поднять собственный OSRM/GraphHopper-сервер на данных OpenStreetMap Москвы или подключить стабильный роутинг-провайдер.

## Что делает алгоритм

- выбирает прогулочную зону Москвы;
- учитывает примерную длину, тему и обязательное место;
- предпочитает близкие и прогулочно ценные точки;
- строит линию маршрута по пешеходной сети OpenStreetMap через OSRM;
- показывает реальную длину и время, когда OSRM доступен;
- считает примерные калории по длине маршрута;
- старается завершить маршрут рядом с метро;
- генерирует альтернативные качественные варианты.

## Подготовка к iOS

Логика уже разделена на два слоя:

- выбор точек маршрута;
- построение пешей линии между выбранными точками.

При переносе в iOS можно оставить алгоритм выбора точек, а слой карты заменить на MapLibre/MapKit/Google Maps, слой роутинга - на собственный OSRM или другой routing API.

## Офлайн-карты

Веб-версия кэширует только те тайлы карты, которые уже были открыты в браузере. Чтобы район был доступен без интернета, заранее откройте нужный маршрут и немного подвигайте карту вокруг него.

Для полноценного офлайн-доступа в iOS лучше использовать заранее подготовленные MBTiles/PMTiles или MapLibre с офлайн-пакетами.

## P1-поверхности

- `routes.html` и `route.html` — индексируемые подборки и карточки готовых прогулок;
- `routes.js` — единый каталог проверенных сценариев;
- `privacy.html` — описание хранения параметров и внешних API;
- `api-config.js` — заменяемые URL OSRM/Nominatim для будущего same-origin proxy;
- история последних прогулок хранится локально и не отправляется на сервер.
